# 04. 위험 요소 분석

> 심각도(S)/발생가능성(L): 상(H)/중(M)/하(L). 우선순위 = S×L.

## 4.1 법적·준법 위험 (최우선)

| ID | 위험 | S | L | 완화책 |
|---|---|---|---|---|
| L1 | ToS 위반 다운로드로 법적 책임 | H | M | Eligibility에 ToS 정책 테이블 강제, 금지 호스트 하드블록, 법무 검토 게이트 |
| L2 | DRM/암호화 콘텐츠 우발적 저장 | H | L | **fail-closed**: EME/암호화 신호 하나라도 있으면 INELIGIBLE, 다운로드 직전 재확인 |
| L3 | robots.txt 무시 자동수집 | M | M | Analyzer 진입 전 robots 확인, Disallow면 SKIP |
| L4 | 저작권 침해 재배포 | H | L | 저장은 사용자 본인 권한 범위로 한정, 재배포 기능 미제공 |
| L5 | 개인정보/로그에 URL·토큰 포함 | M | M | 리포트 민감정보 마스킹, 토큰/쿠키 미기록 |

## 4.2 기술 위험

| ID | 위험 | S | L | 완화책 |
|---|---|---|---|---|
| T1 | MSE/blob로 원본 URL 은닉 → 탐지 실패 | M | H | 런타임 후킹(§3/§4) + Network 상관, 실패 시 CONDITIONAL 리포트 |
| T2 | cross-origin iframe/closed shadow 접근 불가 | M | H | Network 계층 우회 탐지, 프레임 단위 스캔, 한계 명시 |
| T3 | 매니페스트 문법 변형/비표준 태그 파싱 실패 | M | M | 관대한 파서 + 스키마 검증 + 파싱 실패 로깅, 회귀 픽스처 |
| T4 | opaque(CORS) 응답 본문 접근 불가 | M | M | 적격성에 CORS 신호 반영, 서버 프록시/권한 경로는 CONDITIONAL |
| T5 | LIVE 스트림 종료 경계 없음 | L | M | LIVE는 CONDITIONAL/스냅샷 한정 |
| T6 | 세그먼트 재조합 무결성 오류(순서/init 누락) | M | M | init 우선·순서 보존·바이트 검증, 실패 시 폐기 |
| T7 | 후킹이 페이지 재생을 깨뜨림 | H | L | call-through(원 동작 보존), 관측 전용, 회귀 테스트 |

## 4.3 운영·유지보수 위험

| ID | 위험 | S | L | 완화책 |
|---|---|---|---|---|
| O1 | 브라우저/CDP/Playwright 버전 드리프트로 계측 파손 | M | H | 버전 핀·CI 매트릭스·계약 테스트(§08) |
| O2 | 사이트 구조 변경으로 탐지율 저하 | M | H | 픽스처 회귀·탐지율 지표 모니터링 |
| O3 | 확장 스토어 정책 변경(MV3 등) | M | M | 표준 API 준수, 정책 변경 추적 |
| O4 | 대량 요청으로 대상 서버 부하/차단 | M | M | rate limit·동시성 상한·백오프 |

## 4.4 리스크 대응 흐름

```
[신호 불명확/파싱 실패/CORS 불가]
        │
        ▼   보수적 기본값
   CONDITIONAL 또는 INELIGIBLE (절대 자동 ELIGIBLE 승격 금지)
        │
        ▼
   리포트에 사유 기록 → 수동 검토 큐
```

## 4.5 준법 원칙 요약
- **차단 우선(fail-closed)**: 애매하면 저장하지 않는다.
- **우회 금지**: DRM/암호화/접근제어/로그인/ToS 우회 코드는 어떤 형태로도 포함하지 않는다.
- **감사 가능성**: 모든 판정은 근거와 함께 리포트에 남긴다.
