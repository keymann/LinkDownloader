# 08. 유지보수 전략

## 8.1 변화에 대한 취약점과 대응

| 변화 원천 | 영향 | 유지보수 장치 |
|---|---|---|
| 브라우저/CDP/Playwright 버전 | 계측 API 변경 | 버전 핀 + 정기 업그레이드 PR + 계약 테스트 |
| 사이트 구조/플레이어 변경 | 탐지율 저하 | 합성 픽스처 + 탐지율 지표 모니터링 |
| 매니페스트 문법 변형 | 파싱 실패 | 관대한 파서 + 실패 로깅 + 회귀 픽스처 추가 |
| 스토어/플랫폼 정책(MV3 등) | 확장 동작 제약 | 표준 API 준수, 정책 변경 추적 이슈 |
| ToS/robots 변경 | 준법 판정 변화 | 정책 테이블 버전관리 + 주기적 재검토 |

## 8.2 포트-어댑터로 변경 격리

```
        ┌──────────── 안정 코어(변경 적음) ────────────┐
        │  Detector · Playlist Parser · Eligibility ·  │
        │  Report                                       │
        └───────▲───────────────▲───────────────▲──────┘
      포트(인터페이스)      포트             포트
        │                     │                  │
   ┌────┴────┐        ┌───────┴──────┐   ┌───────┴───────┐
   │DOM 어댑터│        │Network 어댑터│   │Download 어댑터│   ← 변동 큰 부분
   │(PW/Ext) │        │(CDP/webReq)  │   │(FSA/stream)   │
   └─────────┘        └──────────────┘   └───────────────┘
```
> 브라우저/도구 변화는 **어댑터에만** 흡수 → 코어·테스트 안정.

## 8.3 계약 테스트(Contract Test)
- 각 어댑터는 포트 인터페이스에 대한 계약 테스트를 통과해야 한다(입출력 스키마·이벤트 순서).
- 브라우저/도구 업그레이드 시 계약 테스트가 회귀 방어선.

## 8.4 관측성(Observability)
| 지표 | 목적 |
|---|---|
| 탐지율(픽스처/실측) | 탐지 파이프라인 건강도 |
| 판정 분포(ELIGIBLE/CONDITIONAL/INELIGIBLE/SKIP) | 준법·품질 추이 |
| 파싱 실패율(포맷별) | 파서 유지보수 우선순위 |
| 다운로드 성공/무결성 실패율 | 재조합 품질 |
| 계측 오버헤드 | 성능 예산 준수 |

## 8.5 릴리스/버전 정책
- 시맨틱 버전. 파서/판정 규칙 변경은 CHANGELOG에 근거와 함께 기록.
- Eligibility 규칙은 **감사 로그**로 변경 이력 보존(준법 추적).
- 정기 의존성 업데이트(주기적 자동 PR) + 보안 패치 신속 반영.

## 8.6 문서/온보딩
- 각 모듈 README(책임/포트/예제), 픽스처 카탈로그, 판정 규칙 표.
- "왜 불가로 판정하는가"의 근거를 문서화(준법 커뮤니케이션).

## 8.7 준법 거버넌스(지속)
- ToS/robots 정책 테이블 **분기별 재검토**.
- 신규 호스트 지원 요청은 준법 검토를 통과해야 파이프라인 편입.
- **우회 코드 유입 방지**: 코드리뷰 체크리스트에 "DRM/암호화/접근제어/ToS 우회 없음" 항목 필수.
